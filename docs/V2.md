# Bản v2 — quản lý công việc nhóm

## Chức năng và quyền

- Đăng nhập/đăng xuất, đổi mật khẩu (12–128 ký tự). Không mở đăng ký công khai.
- Admin tạo thành viên, thay đổi vai trò và khóa/mở khóa; không thể vô hiệu hóa admin cuối cùng. Thay đổi quyền/khóa/đổi mật khẩu thu hồi các phiên đăng nhập.
- Mọi thành viên đăng nhập được xem công việc và bình luận trong cùng một nhóm.
- Admin, người tạo hoặc người phụ trách được sửa/phân công/chuyển trạng thái. Chỉ admin hoặc người tạo được xóa; xóa kèm bình luận/lịch sử và có xác nhận trên UI.
- Công việc có mô tả, người phụ trách, hạn, ưu tiên, tối đa 5 nhãn; trạng thái Chưa làm/Đang làm/Hoàn thành.
- Danh sách và Kanban (chuyển cột bằng bộ chọn trạng thái, dùng được bằng bàn phím), bộ lọc, tìm kiếm không dấu, sắp xếp.
- Bình luận và 100 hoạt động mới nhất mỗi công việc; thống kê theo người phụ trách và xuất CSV các công việc đang lọc.
- Quá hạn dựa theo ngày địa phương trên trình duyệt; task hoàn thành không tính quá hạn.

## Chạy local (PowerShell tại thư mục repository)

```powershell
npm.cmd ci
npm.cmd run admin:create -w backend
npm.cmd run dev
```

Lệnh admin:create hỏi tên, email và mật khẩu (ẩn khi nhập); chỉ tạo admin đầu tiên nếu database chưa có tài khoản. Không có mật khẩu mặc định. Mở http://127.0.0.1:5173 rồi đăng nhập bằng tài khoản vừa tạo; vào Thành viên để tạo tài khoản còn lại. SQLite local nằm trong backend/data/tasks.db, độc lập với dữ liệu Azure.

Dùng Docker Compose: đặt APP_VERSION=v2 trong .env trước khi build. Sau `docker compose up -d --build`, chạy `docker compose exec backend node backend/src/admin.js`, rồi mở http://127.0.0.1:8080. Compose tắt Secure cookie vì chỉ publish loopback HTTP; Azure dùng HTTPS và bật Secure.

## Database và phiên đăng nhập

Migration tự thêm trường mới và bảng thành viên, phiên, bình luận, lịch sử; giữ nguyên task v1. Task cũ chưa có người tạo/phụ trách, admin có thể phân công; completed cũ được chuyển sang trạng thái done/todo.
PostgreSQL dùng transaction/advisory lock; phiên lưu trong database chung nên không cần sticky session giữa replica. SQLite dùng hàng đợi transaction cho local.
Mật khẩu được băm scrypt với salt riêng. Cookie HttpOnly, SameSite=Lax, Secure trên production; token ngẫu nhiên chỉ lưu dạng SHA-256 trong DB, hết hạn sau 7 ngày. API ghi dữ liệu yêu cầu X-Taskboard-Request: 1 để chặn yêu cầu cross-origin; không bật CORS. Rate limit đăng nhập dùng DB chung: 10 lần/email hoặc 100 lần/IP trong 15 phút. Sau đăng nhập đúng, xóa bộ đếm email. Không tin X-Forwarded-For do client gửi; khi sau proxy, giới hạn IP có thể dùng chung cho nhiều người.

## Triển khai một lần lên Azure

1. Test local/UI, commit/push; chạy workflow Publish Docker Images và chờ hoàn thành. Hai workflow đã có PostgreSQL test service. Frontend dùng build-arg phiên bản v2-sha-<commit>.
2. Trên cp, sao lưu PostgreSQL vào file chỉ chủ sở hữu đọc được (lệnh dưới đây chạy trong Bash SSH, không chạy PowerShell):

```bash
umask 077
backup="taskboard-before-team-$(date +%Y%m%d-%H%M%S).sql"
kubectl -n midterm-app exec deployment/postgres -- pg_dump -U taskboard -d taskboard > "$backup"
test -s "$backup" && echo "Backup saved: $backup"
```

Giữ backup ở nơi riêng, không đưa lên Git. Thực hiện trong khoảng bảo trì vì frontend v1 không đăng nhập được với backend mới; khi backend rollout còn lẫn pod v1, pod cũ vẫn là API công khai.

3. Tại clone repository trên cp: `git pull --ff-only`, rồi `bash scripts/deploy.sh <SHA-40-ký-tự>`. Script triển khai backend trước rồi frontend; cập nhật APP_VERSION và Secure cookie trong cùng pod template. Khi lỗi, script dừng và báo image cũ, không tự rollback.
4. Khi backend mới Ready, tạo admin ban đầu đúng một lần:

```bash
kubectl -n midterm-app exec -it deployment/backend -- node backend/src/admin.js
```

Chỉ cần chạy ở một pod vì dùng chung DB. Đăng nhập https://beegun.site, tạo thành viên và xác minh dữ liệu v1. Cookie giữa beegun.site và www.beegun.site là độc lập, nên dùng nhất quán một hostname.
5. Kiểm tra 3 node Ready, frontend/backend 2/2, API health ok, người chưa đăng nhập nhận 401 khi gọi /api/tasks. Khi dùng manifest tĩnh, cập nhật image/APP_VERSION theo SHA mới trước khi apply; YAML v1 vẫn tham chiếu image cũ.

Không chạy lại kubeadm init và không xóa PVC/volume. Nếu rollback về v1, API sẽ trở lại công khai và không có phân quyền; chỉ làm trong bảo trì có giới hạn truy cập. Giữ các bảng/cột mới, không xóa schema. Mật khẩu/quyền và các thao tác xóa không được hoàn tác bằng rollback image.

## Kiểm thử

```powershell
npm.cmd test
npm.cmd run build
docker compose -p taskboard-team-test -f compose.test.yaml up --build --abort-on-container-exit --exit-code-from test
docker compose -p taskboard-team-test -f compose.test.yaml down
```

Test local bỏ qua PostgreSQL nếu không có TEST_DATABASE_URL; Docker/CI chạy đầy đủ trên database tạm. Kiểm thử gồm giữ dữ liệu v1, API CRUD/validation, hai backend chia sẻ phiên/dữ liệu, phân quyền, CSRF header, admin cuối cùng, bình luận/lịch sử, đổi mật khẩu/khóa/đăng xuất và rate limit.

Checklist UI: đăng nhập admin; tạo thành viên; tạo/phân công task; thành viên sửa task được giao nhưng không xóa task của người khác; bình luận; lọc/tìm kiếm; Kanban; thống kê; CSV; đổi mật khẩu và đăng nhập lại.

## Phạm vi

Một nhóm dùng chung dữ liệu; chưa có nhiều workspace, upload file, gửi email/khôi phục mật khẩu tự động hoặc realtime. Nhấn Làm mới để nhận cập nhật của thành viên khác. Chỉnh sửa đồng thời cùng trường dùng lần lưu cuối cùng. PostgreSQL vẫn là một replica trên cp, cần giữ backup.
